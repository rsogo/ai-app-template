# 基盤（NCDC）への依頼文を作る

次のような作業は、利用者やAIが自分で行わず、依頼文を作って利用者に渡す。
**社内への公開は依頼不要**（`main` に push すると自動で公開される。`docs/agent/publish.md`）。

| 依頼の種類 | いつ |
|---|---|
| 新しいアプリの用意 | 新しくアプリを作り始めるとき（DB・ファイル置き場はアプリごと） |
| ファイル置き場の追加 | 画像・添付などを保存したくなったとき |
| 社外への公開 | 社外の人にも見せたいとき |
| 外部サービスとの連携 | チャット通知、外部 API など、鍵が必要なものを使いたいとき |
| データの復元 | 消したデータを戻したいとき（30日以内） |
| アプリの削除 | 使わなくなったとき |
| 基盤の不具合・権限の問題 | 公開が基盤側の理由で止まったとき |

## 依頼文のひな形

```
【依頼の種類】新しいアプリの用意 ／ ファイル置き場の追加 ／ 社外公開 ／ 外部連携 ／ データの復元 ／ 削除 ／ 不具合
【アプリ名】（英数字とハイフン。例: sales-report）
【依頼者】（会社のメールアドレス）
【用途】（何に使うかを一言）
【保存するデータ】（例: 日報の本文、日付。個人情報は含まない）
【DB】使う ／ 使わない
【ファイル保存】使う ／ 使わない
【社外公開・外部連携】なし ／ あり（相手先と理由）
【リポジトリ】（GitHub の URL。新しいアプリの用意では必須）
【補足】
```

- 個人情報・機密情報を扱う必要がある場合は、その旨と理由を補足に書く。
- 鍵やパスワードそのものは依頼文に書かない（受け渡し方法は基盤から案内する）。

## 用意ができたら（NCDC からの完了連絡）

「新しいアプリの用意」が終わると、NCDC から次の値が届く。利用者から受け取ったら `wrangler.jsonc` に反映し、コミットする。
**`wrangler.jsonc` の `database_id`・`vars` を書き換えてよいのは、この時だけ。**

| 届く値 | 書く場所 |
|---|---|
| データベースID | `d1_databases[0].database_id` |
| TEAM_DOMAIN | `vars.TEAM_DOMAIN` |
| POLICY_AUD | `vars.POLICY_AUD` |
| ファイル置き場（依頼した場合） | `r2_buckets` のコメントを外す |
| 公開 URL | （書かない。利用者に伝える） |

反映後に `npm run check` と `npm run build` が通ることを確認してから push する。これが最初の社内公開になる。
